# 오늘, 카페에서 어떤 책을 읽을까?

카페에서의 **상황**과 원하는 **감정**에 맞춰 책을 추천하는 웹 서비스입니다.
API로 수집한 원시 도서 데이터를 LLM 가공 · 다단계 검수 · 인기도 결합을 거쳐 큐레이션 데이터셋으로 만들었습니다.

🔗 **[Live Demo](https://incredible-donut-f7a98e.netlify.app/)**

---

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 추천 기준 | 독서 상황 6개 × 감정 라벨 7개 |
| 최종 도서 | **153권** (수집 202건 → 정제 199권 → 검수 후 153권) |
| 데이터 출처 | 카카오 도서 API · 알라딘 API · Gemini API |
| 산출물 | 정적 웹 페이지 (HTML · CSS · JavaScript) |

---

## 2. 데이터 파이프라인

```
① 수집        카카오 도서 API → 202건
     ↓
② 중복 제거    ISBN 기준 → 고유 199권
     ↓
③ LLM 가공     Gemini로 추천 상황 · 감정 라벨 · 추천 이유 생성
     ↓
④ 결측 보완    소개글 부족 도서는 타 서점 소개글로 보완
     ↓
⑤ 1차 검수     비도서 상품 · BL · 19세 · 목적 부적합 도서 제외
     ↓
⑥ 인기도 결합   알라딘 API → 판매지수 · 평점 · 리뷰 수 · 판매상태
     ↓
⑦ 2차 필터     판매지수 낮은 품절·절판 도서 제외
               (인기 절판 도서는 상태 표시 후 유지)
     ↓
⑧ 보강 · 검수   부족한 상황의 도서 추가 수집 → 표본 검수
     ↓
⑨ 최종 확정    부자연스러운 추천 · 판단불가 도서 제거 → 153권
```

### Gemini 생성 필드

| 필드 | 설명 |
|---|---|
| `primary_situation` | 추천 독서 상황 |
| `mood_label` | 책의 감정 분위기 |
| `recommendation_reason` | 60자 이내 추천 이유 |

## 3. 추천 로직

사용자가 **상황을 선택**하고 **감정 탭**을 누르면 조건에 맞는 도서가 표시됩니다.

**추천 점수 = 판매지수 65% + 리뷰 수 20% + 평점 15%**

추천 버튼을 누르면 인기 상위권 도서 중에서 **가중 무작위(weighted random)** 방식으로 한 권을 제시합니다. 항상 1위 책만 나오지 않도록 하면서도, 품질이 검증된 도서 범위를 벗어나지 않게 하기 위한 설계입니다.

---

## 4. 핵심 과제 — 수집만으로는 추천이 되지 않는다

API 응답을 그대로 쓰면 추천 서비스로 성립하지 않았습니다. 실제로 제외된 항목들입니다.

- **도서가 아닌 상품** — 굿즈·문구류가 도서 검색 결과에 혼입
- **BL · 19세 도서** — 카페라는 공개된 장소의 맥락에 부적합
- **목적 부적합 도서** — 수험서·전문서 등 '카페에서 읽는 책'과 거리가 먼 분류
- **품절·절판 도서** — 추천해도 구할 수 없음 (단, 인기 절판본은 상태 표기 후 유지)

202건 중 **49권(약 24%)이 검수 과정에서 제외**되었습니다. 이 비율이 수집 이후 정제 단계의 필요성을 보여준다고 봅니다.

## 5. 시행착오

| 문제 | 해결 |
|---|---|
| Gemini API 할당량 초과 | 진행 결과를 중간 저장하고 **미처리 도서부터 재개**하는 구조로 변경 |
| 카카오 검색 결과 0건 | 긴 문장형 검색어를 짧은 키워드로 분해<br>`따뜻한 일상소설` → `일상`, `위로` |
| BL · 19세 도서 혼입 | 전체 데이터 수동 검수 후 제외 기준 명문화 |
| 키워드 수집만으로는 인기도 반영 불가 | 알라딘 판매지수 · 리뷰 정보를 결합해 추천 점수 산출 |

## 9. 한계 및 개선 방향

- **데이터 규모** — 153권은 추천 다양성 측면에서 부족. 상황·감정 조합(42개) 대비 희소한 칸이 존재
- **라벨 검증** — Gemini 생성 라벨을 표본 검수로만 확인. 다수 평가자 기준의 일관성 검증 미실시
- **정적 데이터** — 판매지수·평점이 수집 시점에 고정됨. 주기적 갱신 로직 필요
- **개인화 부재** — 사용자 이력을 반영하지 않는 규칙 기반 추천
